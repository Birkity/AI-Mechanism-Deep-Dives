# Thread

## Post 1/6

Raw agreement can look strong for the wrong reason.

If 92% of labels are "correct," two passes can agree a lot just by following the base rate.

So 91.7% agreement is useful, but it is not the full reliability story.

## Post 2/6

Cohen's kappa asks a harder question:

"How much agreement remains after expected chance agreement?"

In Amir's case:

- observed agreement: 91.7%
- expected chance agreement: 84.4%
- kappa: about 0.46

That is a very different headline.

## Post 3/6

But kappa has its own trap.

When one label dominates, expected chance agreement becomes very high. That can depress kappa even when actual disagreement is small.

This is the kappa paradox:

high raw agreement, moderate-looking kappa.

## Post 4/6

The fix is not "raw agreement only" or "kappa only."

Report the bundle:

- raw agreement
- base rates
- Cohen's kappa
- Gwet's AC1 or PABAK
- contingency tables
- per-dimension disagreement review

Reliability needs context.

## Post 5/6

Also name the protocol correctly.

If the same rater labels the same tasks twice after 24 hours, that is intra-rater reliability.

It is not inter-rater agreement until independent raters apply the same rubric.

That distinction changes the claim.

## Post 6/6

The practical takeaway:

91.7% agreement does not prove the rubric is perfect.

0.46 kappa does not prove the rubric is broken.

Together, they say:

"Mostly consistent, high-prevalence labels, needs transparent chance-corrected reporting."
